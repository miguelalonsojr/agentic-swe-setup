# ddd-expert

Use this guide when business terms or rules are hard to pin down and a domain model may help. It starts with examples of allowed and rejected actions, then checks whether terms have consistent meanings across workflows. It explains when identity suggests an entity, when value suggests a value object, and when a business invariant may justify an aggregate boundary.

The guide does not start by assigning a pattern to every noun. If rules are missing, it asks for them. If a simple record is sufficient, it says so. It does not choose databases, services, or implementation interfaces on the strength of domain vocabulary alone.
