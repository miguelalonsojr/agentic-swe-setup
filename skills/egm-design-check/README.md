# Optional EGM design check

The repository-owned `egm-design-check` skill is an explicitly requested comprehension check. It is locally written and inspired by Dave Rensin's [Elephants, Goldfish and the New Golden Age of Software Engineering](https://drensin.medium.com/elephants-goldfish-and-the-new-golden-age-of-software-engineering-c33641a48874) and the [Elephant Goldfish Model project](https://github.com/google/elephant-goldfish-model/tree/403d8881d62022490637d740657b33f01e321ea8). It is not the complete upstream plugin.

Invoke `/skill:egm-design-check <document-path>` to check one existing document, or explicitly ask for an EGM comprehension check of a named document. To select the check for one feature, request it for that feature before approving its full-path design. The feature request replaces the ordinary builder check once at the existing pre-approval point. A one-off request does not edit the document, begin implementation, select future features, or create a global preference. Merely installing the skill or mentioning EGM does not select it.

The review reports Understanding, Material gaps, Coverage and limitations, and Disposition. The exact dispositions are `No material gaps found`, `Needs clarification`, and `Incomplete`. Missing necessary reads, a failed fresh review, or known author-context contamination require `Incomplete`; a clean report is not human approval or proof that the design is correct. The controller saves and links a unique report in session/task artifacts. The reviewer returns text and writes no files.

A fresh child receives the named document, explicitly selected companions, referenced source when needed, and standard instructions. It receives no parent summary. The child is instructed not to fetch family context, start another agent, execute code or tests, or edit files. Fresh conversation history does not isolate the shared filesystem or global guidance, and Prime does not enforce read-only access through this skill. Observed no-write behavior is not a permission guarantee.
