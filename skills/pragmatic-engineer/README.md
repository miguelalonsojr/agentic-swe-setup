# Pragmatic Engineer

Use this skill when a technical decision has several workable answers but uncertain costs. It helps compare what can be shipped now with what will be expensive to change later. It treats duplicated knowledge as a maintenance risk, while recognizing that repeated text does not always mean a shared rule. It also asks for a small end-to-end check that exposes an assumption before the team commits to a larger solution.

The guide prompts concrete security and testing choices: name the failure, its impact, and the cost of a safeguard. It does not certify a design, waive project checks, or claim that a demo proves production readiness. A recommendation should say which facts were observed, which remain estimates, and what would change the decision.
