# generating-design-doc

This skill helps produce an architecture document for an existing codebase. It starts with the repository revision and traces real entry points and representative flows before describing components, boundaries, dependencies, and runtime assumptions. Diagrams must match relationships supported by code and include paths readers can inspect. The finished document separates observations from inferences and lists important unknowns instead of filling gaps with plausible architecture.

Use it when you need a durable technical reference for a system. For a brief reading-order tour of files, request a codebase walkthrough instead. The guide is self-contained; it does not require a references directory or assume a particular diagram renderer.
