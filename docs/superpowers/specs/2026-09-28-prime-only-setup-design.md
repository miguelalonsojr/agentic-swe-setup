# Prime-only agentic-swe-setup design

## Outcome and boundaries

This repository installs Superpowers, `agentic-swe-skills`, local skills, subagent roles, and workflow instructions for Prime Agent only. Prime Agent retains both `prime/anthropic.json` and `prime/openai.json`. The latter uses `openai-codex/...` selectors as a Prime model provider; it is not a separate Codex harness. Installation, update, diagnosis, and regular uninstall do not configure Claude Code, OpenCode, or a standalone Codex harness.

The existing home installation also needs a one-time retirement of items this repository installed for Claude Code and OpenCode. Retirement does not remove unrelated user files or the shared `~/.superpowers` and `~/.swe-skills` checkouts. At the user's request it does uninstall the Claude Code Superpowers plugin. It does not create OpenCode config backups. Historical design and plan records remain historical records, not active instructions.

## Legacy retirement

Provide a narrow, separately invoked retirement path for already-installed Claude Code and OpenCode items. It does not run during normal Prime install, update, doctor, or uninstall. Remove a legacy link only when it resolves into this repository or a known shared skills checkout installed by this setup. For OpenCode, require a valid manifest and strict JSON config; remove only named managed agent/provider values that still equal the corresponding installed repository config, plus the exact manifest-recorded plugin entry. Skip changed or uncertain values and report them. Do not remove unrelated keys, files, or backups. If the config cannot be parsed, leave it intact and report manual work rather than rewriting it. Use Claude Code's own plugin-uninstall command for the Superpowers plugin; treat an absent plugin as already retired. Do not remove the plugin before checking the available uninstall path. Remove a manifest only when its managed entries have been retired or explicitly reported as retained; repeated retirement is safe. The installed Prime manifest, settings, subagent specs, links, and provider selection remain untouched.

## Failures and verification

The retirement command reports skipped paths and returns a failure for a required cleanup it could not safely complete; it never substitutes a destructive wildcard. A dirty or non-fast-forward shared checkout stops its update. Missing tools are reported without claiming installation success.
